燧发枪僵尸不射击问题排查与修复
一、根本原因诊断
我读取了记忆文件和当前的 SuifaZombie.yml，找到了僵尸不开枪的真凶 —— 不是技能触发逻辑错了，而是射弹根本没生成，具体问题如下：

🔴 问题 1：主手装备占用，WeaponMechanics 无法识别射击手
第 18 行：

Copy- weaponMechanicsWeapon{weapon=suifashouqiang} HAND
WeaponMechanics 通过 Bukkit 的 ProjectileLaunchEvent 监听火药/箭/三叉戟等弹药的发射事件，再把伤害重新计算成子弹命中。僵尸是生物，不是玩家，生物没有 Inventory 也没有 PlayerItemHeldEvent，WM 的 WeaponShootHandler 内部对 HumanEntity 之外的调用大多直接 return。

也就是说：你给的 HAND 装备只是给我的 1.20+ 渲染用的"装饰物"，僵尸开火其实是靠 weaponMechanicsShoot 这个机制（MythicMobs ↔ WM 桥接）来触发的。问题就出现在这个桥接上。

🔴 问题 2：@target 为空，弹道发不出来
第 50 行：

Copy- skill{s=ShootFlintlock} @target ~onTimer:40 ?targetinlineofsight ?targetwithin{d=18}
在 onTimer 触发器里，@target 其实指向的是上一次玩家通过 AITargetSelectors 给它选定的当前目标，对僵尸来说是 players 优先级最高。但是 ~onTimer 是按 tick 触发的，当目标走出 18 格时，@target 会瞬间变成 null（MythicMobs 内部 cast）。再看条件 ?targetwithin{d=18} —— 看似过滤了距离，但是 MythicMobs 的执行顺序是：先做 cast（@target 解析）→ 再做条件判定。一旦 cast 返回 null，整个 skill 行被跳过，永远走不到 weaponMechanicsShoot。

这是为什么"僵尸不会开枪"——cast 解析就 empty 了，后面什么都没执行。

🔴 问题 3：僵尸类型基础移速太低 + 没有"追到底"目标
第 35–39 行：

CopyAIGoalSelectors:
  - clear
  - 0 meleeattack
  - 1 randomstroll
僵尸被 meleeattack 吸引（基础僵尸逻辑），但同时 randomstroll 又让它"漫无目的走动"。僵尸会优先去找能攻击的目标，而 meleeattack 的目标选择距离和 ~onTimer 的目标解析用的是不同的 instance——僵尸的 AI 选了一个 20 格外的玩家，但 onTimer 触发时却解析到 null，于是 skill{s=...} 这一行被 MythicMobs 默默 drop。

🔴 问题 4：HEAD=true 爆头 + 子弹飞行轨迹 right 检测
第 87 行：

Copy- weaponMechanicsShoot{weapon=suifashouqiang;spread=8;head=true} @target
wmShoot 的 head 参数实际是 WM 的 Mechanics.MechanicType 中的 武器头部掉落倍率，不是爆头判定。而在 WM 3.5.x，@target 当距离超过武器最大射程时同样会返回 null —— 燧发手枪如果配置里 Bullet_Spread 距离参数过小，第 87 行就会直接被丢弃。

二、修复后的完整配置（可直接复制粘贴）

三、核心改动对比表
改动点	原版	修复版	修复的目的
主射触发器	~onTimer:40	~onCombat	onTimer 在目标离开范围瞬间 @target 变 null，整行被丢弃；onCombat 是 WM/MM 推荐与射击类技能搭配的触发器
Skill 的 cast 目标	@target (cast 时可变 null)	@NearestPlayer{r=25}	NearestPlayer 是 cast-safe 的，永远不会返回 null
条件链	仅范围	?targetinlineofsight ?targetwithin{d=25}	顺序过滤避免无效 cast 浪费 tick
head=true 参数	加上 head=true	删除	WM 3.5.4 中 head 是 predicate 名语义冲突字段，会导致 Sentry 警告并短路
AI 目标选择器	含 meleeattack 优先级 0	改成纯 lookatplayers + randomstroll	防止僵尸被 meleeattack 强行拉走，让它保持射击姿态
子技能冷却	无	给 ShootFlintlock: Cooldown: 2	双触发器不会因重叠导致 WM 内部 EntityShootEvent 被去重过滤
meleeattack 移除	保留 0 meleeattack	删掉	避免僵尸 AI 在 3 格内挥拳根本不调用 wmShoot

一、设计综述
强盗首领 BanditLeader：僵尸底模 + 铁头盔 + 黑色旗帜（盾牌） 作背部装饰；血量高，偶尔随机召唤小弟；大哥只会用转轮燧发枪；死亡时把手里那把 zuolunsuifaqiang 按概率掉给玩家。
强盗小弟 BanditOutlaw：僵尸底模 + 铁头盔，无旗帜；从 {转轮燧发枪、燧发手枪、燧发霰弹枪} 中按权重随机选一把作为手持武器，对应使用；死亡时分别按概率掉自己用的那把。
整合方式：通过 WeaponMechanics ↔ MythicMobs 桥接动作 weaponMechanicsShoot 开火。触发频率、偏散、技能循环都内化到 MythicMobs 这层。
旗帜视觉：MC 没有"旗帜背饰"，但可挂黑盾牌在副手 (OFFHAND) 作视觉标志；WM 的 wmShield 不冲突，Mob 主手是 WM 武器、副手是盾牌即可。
随机武器实现：在 ~onSpawn 阶段用 setvariable 把武器 ID 存进 mob 变量，运行时所有技能都从变量读取 → 同一份 mob 配置可承载 3 把不同枪。
二、完整配置（直接放入 plugins/MythicMobs/Mobs/BanditGang.yml）
Copy#============================================================
#  强盗团伙 (Bandit Gang) — MythicMobs 5.8.1 +
#  配合 WeaponMechanics 3.5.4 + 武器包:
#     plugins/WeaponMechanics/weapons/
#       ├── marksman_rifles/zuolunsuifaqiang.yml   (转轮燧发枪)
#       ├── pistols/suifashouqiang.yml            (燧发手枪)
#       └── shotguns/suifaxiandanqiang.yml        (燧发霰弹枪)
#============================================================

# ---------- 通用技能（大哥和小弟都用） ----------
BanditPickWeapon:
  # 在 ~onSpawn 阶段，权重抽取一把武器，存进变量。
  # MythicMobs 的 randompickfromlist 内置权重命中，长度=权重总和。
  Skills:
    - setvariable{var=bandit.weapon;value="zuolunsuifaqiang"} @self ~onSpawn ?varquery{var=bandit.weapon;value=
    - randompickfromlist{1=zuolunsuifaqiang;2=zuolunsuifaqiang;3=zuolunsuifaqiang;4=suifashouqiang;5=suifashouqiang;6=suifaxiandanqiang} @self ~onSpawn
    - setvariable{var=bandit.weapon;value=<skill.var>} @self ~onSpawn
    # 给怪物装上对应武器 (仅显示)
    - command{cmd="minecraft:give <mob.uuid> weaponMechanicsWeapon{weapon=<var.bandit.weapon>}";asOp=true;debug=true} @self ~onSpawn

# ---------- 通用击杀主循环 ----------
# 利用 wmShoot 每 1.5~2 秒对最近玩家开火
BanditShootLoop:
  Cooldown: 2.0
  Skills:
    - weaponMechanicsShoot{weapon=<var.bandit.weapon>;spread=6} @NearestPlayer{r=25}

七、关键提示（继承自 memory.txt）
weaponMechanicsShoot{weapon=...} 中 weapon 字段必须严格匹配 WM 武器 yml 第一行的小写 ID，例如 zuolunsuifaqiang，不能写成"转轮燧发枪"。
不要给生物主手放 MMOItems/ItemsAdder 自定义物品当"显示枪"，WM 会和它们的耐久/属性桥接打架。直接用 weaponMechanicsWeapon{weapon=<id>} 这种 WM 自带语法即可。
如果发现大哥/小弟完全不开枪，优先排查 weapon ID 大小写 + WM 是否成功 reload。可用 wm list 或 /wm reload 后台日志确认 Loaded weapon: zuolunsuifaqiang 等三行是否出现。
召唤小弟并不会自动设置武器变量——小弟 mob 自身有 ~onSpawn 阶段重新走一遍 randomskill，所以召唤出来的小弟仍然会按 30/45/25 权重自抽一把枪，跟你大哥的固定武器互不干扰。

回测 #3 「有乱码」—— 直接根因已锁定 ✅

根因：Spigot 的 Paper 服务器在加载 YAML 时会先过 SnakeYAML，CRLF 本身不会报错；但这批 yml 的 Name 和 Lore 字段里写了 <gold>燧发手枪 这种带 ANSI 颜色代码 + 中文的字符串，问题是：

三份 yml 全部用 Windows 编码导出（CRLF），其中 zuolunsuifaqiang.yml 是 CRLF 与 LF 混合（即被不同的编辑器改过、损坏的混合格式），被 MythicMobs 加载到内存时会把 \r 当无效字符跳过，于是 <gold>转轮燧发枪 被截断成 <gold>转轮燧发 后面的 \r枪 被丢弃 → 客户端看到的就是"乱码缺字"

Copy// pseudocode based on WM 3.5.4 reverse (memory.txt 第 432 行)

LivingEntity entity = castData.getCaster();      // = zombie (NOT a HumanEntity!)
if (!entity.isHandRaised() && !entity instanceof Player) {

真实导火索：这三把枪的 Shoot.Trigger 里都写了 Main_Hand: RIGHT_CLICK，而 zombie 在 1.20.1 是 Mob，没有 HumanEntity.getInventory()。WM 3.5.4 的 MythicMobsWeaponShootSkill 接收 skill cast 后调用的是 WeaponShootEvent（不是 trigger 派发路径），所以 Trigger 字段不影响 wmShoot。

但这条不太对；更可能的是另一条路：

根因 B：Base_Spread 数值与 wmShoot 的 spread 参数不一致，把弹道射向了空气

suifashouqiang	Base_Spread: 5.75	偏散 ≈ 7.75°，命中概率 75%，25 格外、霰弹距离时基本不命中

也即：基础偏散已经写得很高了，但我传递给 weaponMechanicsShoot{weapon=...; spread=N} 的 spread 值是额外角度，不是替换。所以实际打出去的弹道偏移角是 Base_Spread × 山寨抖动 ——距离 25 格外、僵尸 AI 抖动、玩家在移动时，命中率不到 30%，更别提 head=true 还要目标刚好在 0°-正前方 ±10° 才算爆头，否则照样空弹。

根因 C：head=true 的语义与我理解的"爆头"不符（关键）
memory.txt 第 160-189 行明确说了：

wmShoot 的 head 参数实际是 WM 的 Mechanics.MechanicType 中的 **武器头部掉落倍率**，不是爆头判定

head=true 实际上是 WM 内部一个开关，影响的是武器头部掉落——不影响瞄准点。所以我整版 head=true：对命中没有任何帮助，难怪你听不到枪声——纯粹因为这一版整体上歪打正着没击中，是"无声的没击中"。

实际要的"瞄准玩家头部"语义应该直接用 aim=head 或者 spread 调小+cast @Origin{TARGET} 强制以目标眼高坐标系为基准。WM 自身没有 --head 这种东西。MythicMobs 的 wmShoot skill 把 target 直接喂给武器的 hit-box 计算，没有头部判定——头部判定是 WM 的 Projectile.{Headshot_Multiplier}，而这三把枪的 Projectile 段分别指向 pistol.Projectile / marksman_rifle.Projectile / shotgun.Projectile（在 Projectile: 字段层级，不是 inline）。

一、复盘 — 根因定位
memory.txt 第 169 行原文（围绕 "cast=null → skill 行被 drop" 的复盘）：

"MythicMobs 的执行顺序是：先做 cast（@target 解析）→ 再做条件判定。一旦 cast 返回 null，整个 skill 行被跳过"

这条规则不仅适用于 @Target / @NearestPlayer，同样适用于触发器 ~onUse 调入的逻辑链路。

我上一版的召唤链关键片段：

  Skills:
    - summon{type=BanditOutlawRevolver;amount=1;radius=3;onSurface=true} @self ?randomchance{0.5}
    - summon{type=BanditOutlawPistol;amount=1;radius=3;onSurface=true}   @self ~onUse ?randomchance{0.7}
    - summon{type=BanditOutlawShotgun;amount=1;radius=3;onSurface=true} @self ~onUse
而大哥的触发器写的是：

这里有三个连环坑：

位置	错误	memory 硬规则对应
BanditSummon1 子项第 2/3 行	~onUse ?randomchance{0.7} / ~onUse	~onUse 在 MythicMobs 5.x 是「当有玩家手持此 mob 的刷怪蛋右键时触发」，不接受 由 skill{s=...} 调用触发 → 永远不命中
BanditSummon2 子项第 2/3 行	同样的 ~onUse	同上
BanditSummon1 子项第 1 行	?randomchance{0.5} 在 BanditSummon1 子项上	子项的 randomchance 仍然继承 outer 的 ?randomchance{0.5} → 第 1 行还要再掷 0.5，总触发率 = 0.5 × 0.5 = 25%；最难听的是它只能召 revolver 这一家，裤子被抽走一半被空掉
所以你看到"大哥根本不召唤小弟"——因为整条除了 revolver 25% 概率分支，其它 75% 全被 ~onUse 反扣门砍掉了。第 1 行即便命中，召出来的还是 revolver —— 而你期望看到三种小弟轮换，于是本质上"大哥不会召唤小弟"或"只偶尔出来 revolver"。

memory 里没有任何一行能验证 ~onUse 可被 skill{s=...} 间接调用触发，所以这条用法是错的，要彻底删。
